# 勤怠管理アプリ_改良草案

## 概要

勤怠管理アプリの改善案を決めるファイルです。

## 課題

### アプリ内の課題

- コードが煩雑
  - viewでの実装が統一されていない。I18n(多言語)に対応した記述もあれば、そのまま日本語を埋め込んでる記述もあったり。
  - MVCの責務分離が不十分。view層でデータを加工している記述が残っている。
    - RailsのログでDBのクエリ数≒カラム数になっていない可能性が高いので、特に見直す。
  - 共通している処理を共通化しきれていない...気がする。

- UIが不完全
  - ヘッダーアイコンが現状並べただけであり、画面が小さいとアイコンが縦列になる。その分画面を大きく占有してしまい、使いづらくなる。
    - Bootstrapのテーブル機能を用いた実装を見直す
- 通知機能が簡易的
  - 「申請承諾」「申請否決」といった結果通知をテキストで表示するのみで、申請修正などに遷移できない。

- 業務ルールが簡易的
  - 有給管理がかなり簡易的
    - 有給付与、消化の際の有給をカウントする機能が未実装。
  - 残業機能がない
    - 規定残業時間の設定や残業時間カウントなど
  - 日を跨いだ夜勤打刻に対応していない
  - 遅刻、早退の判定がない
  - 月末締めの機能（勤怠実績の可視化や締め後の機能制限）
  - 会社全体での休日指定機能
  - 夜勤時間のカウント機能

### アプリ外の課題

- githubの使い方が我流
  - issueを使っていない
  - プッシュのコメントを雰囲気で書いている(ルールがない)
┗docs/git_rules.mdに今回の使い方ルールを追加

- Qiitaに記事を1個しか上げられていない
  - 活動実態が見えにくい

## 改良内容

### 機能要件

- ユーザー登録、ログイン機能(device)
- 一般ユーザーの機能

  - 勤怠登録
    - 出勤、退勤、休憩開始、休憩終了の打刻機能
    - 押し間違えた5分以内の打刻の消去機能
    - 押し間違えた打刻の修正申請機能
    - 【新】日を跨いだ夜勤打刻機能
    - 【新】コアタイムを跨いだ打刻の遅刻、早退判定機能

  - 自身の情報確認
    - 登録名やメールアドレスの確認
    - 与えられた就業ルールの確認
      - 出勤する曜日の確認
      - コアタイム・休憩時間上限を確認
      - 【新】各追加機能（有給、残業）の時間数確認機能

  - 振替出勤/休暇申請
    - 振替出勤、有給休暇、病欠を理由とした例外日の申請機能

  - 通知機能
    - 各申請の承認/却下確認のための通知機能
    - 【新】差し戻しの際に再申請する機能を追加。

  - 【新】月末締め機能
  - 【新】有給カウント機能（時間単位）
  - 【新】残業時間カウント機能
  - 【新】夜勤時間カウント機能

- マネージャー権限を持つメンバーの管理機能
  - ユーザーの情報確認
    - ユーザーの登録名やメールアドレスの確認
  
  - 管理者に割り当てられたメンバー（部下）の管理機能
    - メンバーの打刻修正申請の承認/却下機能
    - メンバーの振替/休暇申請の承認/却下機能
    - メンバーの就業規則の更新機能
    - 【新】メンバーの打刻実績表示機能
      - Chart.jsを用いたグラフ表示
    - 【新】メンバーの月末締め承認機能
  - 【変更】メンバーを自由に登録する機能の廃止
  - 【新】申請承認を行う代理人の設定機能
    - 休暇設定時に代理人を指定できる機能

- 管理者権限を持つユーザーの管理機能(主に人事担当がこの権限を持つ)
  - 全ユーザーの情報確認機能
  - 【新】権限の設定機能
    - {リーダー、メンバー}や、{部長、課長、一般}など、階層構造を持つ権限の設定
  - 【新】全ユーザーの状態変更機能
  - 【新】有給休暇一斉付与機能
    - 勤続年数に応じた有給の一斉付与
  - 【新】役員やトップに人事の変更を通知する機能
